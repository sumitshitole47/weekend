# 📜 AI Development Rules & Boundaries

## Rules for AI Assistants working on AeroTwin-3D

This document sets strict operational boundaries, code quality standards, and architectural rules for any AI agent or assistant contributing to the **AeroTwin-3D** codebase.

---

## 🛑 Strict Prohibitions & Anti-Patterns

1. **NEVER Mock 3D Geometry or Photogrammetry Outputs**:
   - Do NOT use math jitter generators (e.g. `Math_jitter()` or random point clouds) to simulate 3D models. All 3D point clouds and meshes MUST be generated by real COLMAP SfM/MVS reconstruction.
2. **NEVER Fall Back to Stale Artifacts Silently**:
   - Do NOT display or return previously reconstructed 3D models when a new video is uploaded. Before saving a new upload, stale outputs in `data/colmap_output/` MUST be explicitly purged via `purge_stale_outputs()`.
3. **NEVER Commit to Git Without User Approval**:
   - Do NOT run `git commit` or `git push` without explicit approval from the user.
4. **NEVER Swallowing Errors or Masking Exceptions**:
   - Do NOT wrap critical COLMAP or file system operations in silent `try/except: pass` blocks without logging. If COLMAP produces 0 points, the system MUST raise an explicit exception and update status to `"error"`.
5. **NEVER Bypass GPU Acceleration**:
   - All COLMAP sub-commands (`feature_extractor`, `exhaustive_matcher`, `patch_match_stereo`) MUST target NVIDIA CUDA GPU Device 0.

## 📦 Approved Dependencies & Libraries

### Permitted Libraries
* **Backend**: `fastapi`, `uvicorn`, `starlette`, `pydantic`, `pyyaml`
* **Computer Vision**: `opencv-python` (`cv2`), `numpy`, `scipy`
* **3D & Photogrammetry**: `open3d`, `trimesh`, `laspy`, `tifffile`
* **Frontend**: Three.js (via CDN/static bundle), Tailwind CSS, Vanilla JS / HTML5

### Prohibited / Avoided Dependencies
* Heavy deep learning frameworks (`torch`, `tensorflow`, `torchvision`) for core SfM/MVS unless explicitly requested by user (keeps processing lightweight and $< 15\text{ min}$).
* Unverified third-party paid cloud APIs.

## 🔧 Configuration Integrity Rules

1. **Single Source of Truth**:
   - All parameters (FPS, SIFT max features, blur thresholds, PatchMatch stereo settings, Poisson depth, telemetry defaults) MUST be read from [config.yaml](file:///c:/Users/shito/.gemini/antigravity/scratch/sih26158_drone_3d/config.yaml).
2. **Built-in Fallback Security**:
   - In [pipeline/config.py](file:///c:/Users/shito/.gemini/antigravity/scratch/sih26158_drone_3d/pipeline/config.py), if `config.yaml` is missing or corrupted, the system must deep-merge missing keys with `DEFAULT_CONFIG`.

## 🛡️ Error Handling & UI Feedback Standards

1. **Validation at Ingestion**:
   - Uploaded videos MUST be valid MP4/MOV containers.
   - Uploaded SRT logs MUST contain parseable timestamps overlapping with video duration.
2. **Informative HTTP Status Codes**:
   - Raise `HTTPException(status_code=400, detail="...")` for invalid uploads.
   - Raise `HTTPException(status_code=404, detail="...")` for missing deliverables.
3. **No-Cache Headers**:
   - `GET /api/model/current.ply` MUST always include:
     ```headers
     Cache-Control: no-cache, no-store, must-revalidate
     Pragma: no-cache
     Expires: 0
     ```
